# UPPAAL model of the ML-KEM Braid

`spqr_uppaal.py` writes an UPPAAL model of the braid in
`Spqr/Specs/Braid/StateMachine/Model.lean` and replays monitor traces
(the JSONL logs of the cargo feature `monitor`) against it. `braid.xml`
is the free model, generated by `spqr_uppaal.py model braid.xml`. The
script reads traces with `scripts/spqr_trace.py`.

## Model

The system has three processes. `Alice` and `Bob` are instances of the
template `Party`. It has one location per `Label` and one edge per
numbered transition (1) to (13) of `send` and `receive`. `Net` stores the
sent messages and delivers any of them, so loss, duplication and
reordering are possible. The model has no clocks.

The data is abstract:

- An epoch is a bounded integer. The bound is the largest epoch in the trace
  (3 in the free model).
- A message is a pair (epoch, kind). Chunk indices and bytes are not in the model.
- One token per step stands for the decoder, the MACs and the `ek` check:
  `T_NONE`, `T_PART` (the decoder has no message yet), `T_OK`,
  `T_BAD` (the check fails) or `T_MISS` (the call that the model needs is
  missing, or its input is not the model's input).

UPPAAL sees only the token. The script computes it from the logged calls of
the operation, at one of three levels (`--data`):

- `control`: the code's own result. The model sees only the control flow.
- `calls`: `T_MISS` if the operation made no `hmac` call, else the code's
  own result.
- `formula` (default): `T_MISS` if no `hmac` call has the input of
  `MacHdr` or `MacCt` (`PROTOCOL_INFO`, the label, the big-endian epoch,
  `hdr` or `ct1 || ct2`). On a receive, `T_BAD` if the computed MAC is not
  the received MAC. The `ek` token is the logged result of
  `mlkem.ek_matches_header`.

The script does all byte comparisons. A byte-level fault, such as a MAC over
the wrong input, reaches UPPAAL only as `T_MISS` or `T_BAD`.

## Trace observers

`trace` and `check` add a template `Obs` that replays the first session of
the trace. It has one location `step_k` per step: k steps matched, step k
expected. Each edge of `Obs` checks the state after a step and announces
the next one. `E<> Obs.done` holds if the whole trace is a run of the
model. `sup: matched` gives the largest k. If k is below the number of
steps, step k is the rejected step. `check` runs `verifyta` (path in
`$VERIFYTA`) and writes the witness of `E<> Obs.step_k` (the prefix up to
the rejection) as a `.xtr` file, which the Symbolic Simulator opens.

```bash
python3 -I scripts/uppaal/spqr_uppaal.py trace TRACE.jsonl OUT.xml --max-ops 700
python3 -I scripts/uppaal/spqr_uppaal.py check /tmp/spqr-traces-R2-branch/v1.test.chaos.jsonl --max-ops 700
```

Options: `--party A|B` replays one party and does not check delivery,
like the per-party verdict of the Lean monitor. `--drop-idle` removes the
steps that send or receive `none` and leave the state unchanged.

## What the abstraction loses

- Key agreement and key bytes: the observer compares key epochs only.
- The MAC key: `formula` compares the MAC input, not the key, so a mutant
  that keys the MAC with the wrong key (R1) is not found.
- Chunk contents and indices: erasure coding is one token per step, and a
  receive needs only some sent message of the same epoch and kind.
- Delivery of `none` messages in trace mode: they need no prior send.
- With `--data control`, MAC and `ek` checks are the code's own verdicts,
  so M1, R2 and R3 are accepted. With `--data calls`, R2 and R3 are accepted.
  With `formula`, the script gives `T_MISS` to the R2 and R3 steps whose
  `hmac` input is wrong, and no edge of the model accepts `T_MISS`.
